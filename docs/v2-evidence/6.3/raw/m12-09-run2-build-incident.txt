Task 6.3 completion pass — browser run 2 was run against a mis-built bundle
==========================================================================

Captured 2026-10-06 (UTC). Recorded because it explains run 2's failures and
because a harness run must never be able to reach a non-harness API.

What happened
-------------
Run 1 used the bundle `harness/bin/harness up` built. That script exports a
same-origin sentinel (`VITE_API_BASE_URL=https://apply.beanola.com`) before
`bun run build`; Vite gives process env precedence over .env files, so the
bundle calls its own origin and the tenant resolves from the Host header.

Before run 2 this pass rebuilt `apps/admissions/dist` with a plain
`bun run build` (no sentinel). That build read `apps/admissions/.env.production.local`
(gitignored, developer-local), whose VITE_API_BASE_URL host is api.mihas.edu.zm.
Caddy bind-mounts dist/, so run 2 served that bundle.

Effect: the SPA's session bootstrap went to https://api.mihas.edu.zm instead of
the harness. Every journey that renders the wizard found no session and was
redirected to /auth/signin — F1 (both projects: the gate recorded the sign-in
navigation failing while offline) and F3 (both projects: wizard-action-bar never
appeared; the page snapshot is the sign-in form). Journeys that only use API
contexts (F2, F4-F9) passed.

Was anything outside the harness contacted?
-------------------------------------------
No. `getent hosts api.mihas.edu.zm` on this machine: "does not resolve". A
browser request to an unresolvable host fails at name resolution and never
leaves the machine. The run-2 Playwright stdout contains 0 occurrences of the
hostname. Requests to that host would have been anonymous in any case (the
fresh browser contexts hold no cookies for it), but none could be sent.

Probably also M10's last runs
-----------------------------
M11 raw/60 records that the only two M10 runs started after the final build
(dist/index.html 18:09:42) both failed F3 at "wizard-action-bar not visible", and
M10's error-context.md is the same sign-in page. That is the signature above. It
is stated as a likely cause, not a proven one — M10's bundle is gone.

Fix (process, not code)
-----------------------
From run 3 on, dist/ was rebuilt only through `harness/bin/harness build`, and
each rebuild was checked for the external API hosts baked into the bundle:

  $ grep -ho 'https\?://api\.[a-zA-Z0-9.-]*' dist/assets/js/*.js | sort | uniq -c
        1 https://api.beanola.com      <- PRODUCTION_API_ORIGIN constant in
                                          lib/apiConfig.ts, used only when the
                                          page origin is apply.beanola.com
  (no api.mihas.edu.zm)

Run 2's report is retained as m12-10-playwright-adversarial-run2.txt for the
record; it is not counted as evidence for or against the change.
