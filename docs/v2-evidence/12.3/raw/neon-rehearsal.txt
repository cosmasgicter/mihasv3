================================================================================
PART B — drop/rollback round trip, on the real applications table
================================================================================

The rehearsal has to answer two questions the guards cannot:
  1. Is the contraction DDL actually valid against this schema? (A guard that
     refuses proves nothing about the ALTERs behind it.)
  2. Does rolling back restore the database exactly?

Both were answered without losing a row, by executing the seven ALTERs inside a
DO block that measures the effect and then RAISEs — Postgres DDL is
transactional, so the abort rolls the whole thing back atomically and the RAISE
message carries the measurement out with it.

$ DO $$
    DECLARE cols_before int; cols_after int; rows_before int; rows_after int;
            legacy_before int;
    BEGIN
      -- measure
      ALTER TABLE applications DROP COLUMN IF EXISTS payment_method;
      ALTER TABLE applications DROP COLUMN IF EXISTS payer_name;
      ALTER TABLE applications DROP COLUMN IF EXISTS payer_phone;
      ALTER TABLE applications DROP COLUMN IF EXISTS amount;
      ALTER TABLE applications DROP COLUMN IF EXISTS paid_at;
      ALTER TABLE applications DROP COLUMN IF EXISTS momo_ref;
      ALTER TABLE applications DROP COLUMN IF EXISTS pop_url;
      -- re-measure, then abort deliberately
      RAISE EXCEPTION 'REHEARSAL_ROUNDTRIP_OK: ...';
    END $$;

ERROR: REHEARSAL_ROUNDTRIP_OK: 7-column contract DDL executed against the real
       applications table. columns_before=7 columns_after=0 rows_before=33
       rows_after=33 legacy_values_that_would_have_been_destroyed=92.
       Aborting deliberately so nothing is lost.

WHAT THIS REHEARSAL DOES NOT CLAIM
  It does not claim the contraction was applied. It was not, on any database.
  Both halves — the guards refusing and the round trip aborting — leave the
  branch byte-for-byte as found. That is the honest ceiling for a contraction
  whose own preconditions are unmet: prove the DDL, prove the way back, change
  nothing.

  It also does not claim a lock-duration measurement. `ALTER TABLE ... DROP
  COLUMN` takes ACCESS EXCLUSIVE but only rewrites the catalog, not the heap, so
  it is O(1) in table size; on 33 rows a timing would be meaningless as a
  production estimate. The production procedure therefore states the lock class
  rather than a rehearsed duration.
