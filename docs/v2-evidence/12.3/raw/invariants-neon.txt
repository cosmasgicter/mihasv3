GATE 3 — payment projection mismatch   (ADR-001, R15.9)
--------------------------------------------------------------------------------
branch br-jolly-pine-ahybtg2e:

 applications_total                   | 33
 no_ledger_rows_projection_undefined  | 20
 projectable_rows                     | 13
 projection_mismatches                |  1

the mismatching row (application_number only; no PII):

 application_number | stored   | derived  | ledger_statuses
--------------------+----------+----------+-----------------
 KATC202541031      | rejected | not_paid | expired

VERDICT: FAIL, 1 row. Root cause is a vocabulary gap between two canonical
constants, not corrupt data:
  * `_ADMIN_REVIEW_STATUS_MAP` (backend/apps/documents/payment_helpers.py:468)
    lets an admin write 'rejected' straight onto applications.payment_status.
  * `APP_PAYMENT_STATUS_PRECEDENCE` (payment_constants.py) can only ever derive
    verified / deferred / pending_review / failed / not_paid.
'rejected' is therefore a value the projection can never reproduce, so any row
carrying it is a permanent mismatch by construction. Attributed to the payment
lane (task 8.2 owns the projection); §6.3 of the README states why 12.3 did not
change either constant.

The 20 rows with no ledger row are counted separately, not as mismatches:
`derive_application_payment_status()` returns None for them and its contract is
that the caller leaves the stored summary alone.
