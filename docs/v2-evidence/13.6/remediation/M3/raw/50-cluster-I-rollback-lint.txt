## M3's verdict on cluster I
================================================================================

VIOLATIONS: 26 across 9 files  ->  2 across 2 files
TESTS:      2 failed           ->  2 failed   (the cluster is NOT closed)

The lint was too narrow in 3 of its 4 classes. 13.4 §6.1's classification was
correct and is reproduced exactly:

  INSTRUMENT-A  16 / 4 files  DO-block regex demanded whitespace around $$    FIXED
  INSTRUMENT-B   6 / 1 file   ALTER TABLE IF EXISTS ... DROP not accepted     FIXED
  INSTRUMENT-C   2 / 2 files  an inert read-only SELECT 1 not accepted        FIXED
  SPEC-GAP       2 / 2 files  genuinely data-restoring rollbacks              LEFT FAILING

What was NOT done, and why:

  * No file was allow-listed. The three fixes are to the *patterns*, and each is
    a spelling Postgres already accepts:
      - `END$$;` is `END $$;`  (and the tag is now required to match, which is
        STRICTER than the pattern it replaced)
      - `ALTER TABLE IF EXISTS t DROP CONSTRAINT c` is the idempotent form of
        `ALTER TABLE t DROP CONSTRAINT c` -- more defensive, not less safe
      - `SELECT 1` moves no data; a read cannot destroy a row

  * Five discrimination tests were added so the widening is distinguishable from
    a weakening. The one that matters is
    `test_a_select_wrapping_dml_is_still_rejected`: Postgres lets
    `WITH x AS (DELETE FROM t RETURNING *) SELECT * FROM x` destroy rows while
    beginning with `WITH`, so the read-only branch requires the absence of
    INSERT / UPDATE / DELETE / MERGE anywhere in the statement.

  * The 2 SPEC-GAP violations were NOT absorbed:

      2026_07_25_01_canonical_subject_catalog_rollback.sql
        UPDATE subjects SET is_active = true WHERE code IN ('ADD_MATH','MUS','PHYS')
          AND is_active IS DISTINCT FROM true
        owner: subject-catalog lane

      2026_07_26_02_document_current_slot_alignment_rollback.sql
        WITH ranked AS ( SELECT id, row_number() OVER w AS v, ... ) ...
        owner: document lane

    Both are correct AS ROLLBACKS and both are outside R9.2's closed set, because
    the forward scripts they undo changed DATA, and the inverse of a data change
    is a data change. R9.2's closed set presumes an additive-schema forward
    script. That is a genuine specification gap, it is the one 13.1 suspected and
    13.4 located, and closing it means either widening R9.2's closed set for
    data-migration rollbacks or rewriting two other lanes' scripts to abandon the
    restore. Neither is M3's decision to take: an acceptance criterion is not
    edited without input.

So: the LINT was too narrow (24 of 26), and the two that remain are the SCRIPTS
being right about something the requirement does not yet cover.
