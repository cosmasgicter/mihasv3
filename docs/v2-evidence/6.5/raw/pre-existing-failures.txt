Method
------
The whole admissions-v2 spec is in-flight/uncommitted, so the tree already
carries failures owned by other tasks. To prove 6.5 introduces none, the full
`backend/tests/unit/` surface was run WITH the 6.5 change, then every
failing/erroring file from that run was re-run at a BASELINE where the 6.5
change was removed:

  * `git stash` of the tracked 6.5 edits
    (`backend/apps/applications/services.py`,
     `backend/apps/applications/student_submission_views.py`,
     test-fixture updates, `useWizardController.ts`),
  * the new untracked files moved aside
    (`readiness_v2_views.py`, `readiness_v2_urls.py`,
     `tests/integration/test_submission_readiness_6_5.py`),
  * the `/api/v2/student/applications/` route removed from
    `apps/common/v2/urls.py`,
  * the readiness entry removed from `scripts/authority_matrix_registry.py`,
  * the `build_grades(...)` line removed from
    `tests/integration/test_assignment_config_failure.py`.
