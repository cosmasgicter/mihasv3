5. Corrected constraint (defect found by this slice)
===========================================================================
The as-found script shipped two objects that contradicted each other:
payment_id is ON DELETE SET NULL, but chk_payment_fee_quotes_redeemed_binding
required payment_id IS NOT NULL on a redeemed quote — so the FK produced exactly
the state the CHECK forbade and deleting ANY Payment that a quote had funded
failed outright.

Replacement applied to the branch as constraint-level DDL only (guarded
DROP CONSTRAINT + immediate ADD CONSTRAINT, zero-row table, operator-approved):

  BEFORE: CHECK ((status='redeemed' AND payment_id IS NOT NULL AND redeemed_at IS NOT NULL)
               OR (status<>'redeemed' AND payment_id IS NULL AND redeemed_at IS NULL))
  AFTER:  CHECK ((status='redeemed' AND redeemed_at IS NOT NULL)
               OR (status<>'redeemed' AND payment_id IS NULL AND redeemed_at IS NULL))

Verified live on the branch after replacement (see §2) and behaviourally in
§4(c)/(d). Production has never carried either definition, so a first production
apply installs the corrected one directly.
